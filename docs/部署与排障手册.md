## 一、硬件与接线

### 旁路由部署接线
```
R3G WAN口 → 上级交换机（获取192.168.1.66）
R3G LAN口 → 留空！
```

### 严禁操作
> **WAN和LAN同时接交换机 = 二层环路**

现象：dmesg 频繁输出 `br-lan: received packet on eth0.2 with own address as source address`，内核反复 blocking/disabled/forwarding 端口，导致全网瘫痪。

### 指示灯
- 蓝灯常亮：系统正常运行
- 蓝灯闪烁：Breed 模式或系统启动中
- 橙灯：uboot 阶段

## 二、刷机流程（摘要）

### 1. 进入 Breed
按住Reset键通电，蓝灯闪烁后松开。Telnet 连接：
```
telnet 192.168.1.1
```

### 2. 内存启动 initramfs
在Breed命令行中执行：
```
wget http://192.168.1.10/initramfs.bin
flash bank 0x80001000 initramfs.bin
boot linux 0x80001000
```
（IP 192.168.1.10 为 HFS/tftp 服务器地址）

### 3. 系统刷入
内存启动后浏览器访问 192.168.1.1 → System → Backup/Flash Firmware → 上传 `sysupgrade.bin` → 不保留配置刷入。

### 4. 固件版本
```
固件：OpenWrt 23.05.6 r24232-9e2b39e56e
内核：5.15.189
文件：openwrt-23.05.6-ramips-mt7621-xiaomi_mi-router-3g-squashfs-sysupgrade.bin
```

## 三、ShellClash 安装与配置

### 安装方式
SSH 交互式安装（**所有步骤必须在一个 python_executor/SSH 会话中完成**，SSH断开会中断安装）：
```bash
export url='https://fastly.jsdelivr.net/gh/juewuy/ShellCrash@master' && sh -c "$(curl -kfsSl $url/install.sh)" && source /etc/profile &> /dev/null
```
安装选项：1（安装到/etc）→ 1（稳定版）→ 按需选择。

### 订阅导入痛点与绕行方案

| 尝试 | 方法 | 结果 |
|------|------|------|
| 方式1 | Subconverter 在线转换 | GFW阻断 → 全部 503/400 |
| 方式2 | ShellClash 直连导入 | 同上 |

**最终方案（离线生成 YAML）**：
1. 电脑端 Python 脚本下载订阅链接（需代理）
2. base64 解码得到 vless:// 链接列表
3. Python 脚本将 vless:// 链接转为 Clash YAML 格式
4. SSH heredoc 上传到 R3G 的 `/tmp/config.yaml`
5. `cp /tmp/config.yaml /etc/ShellCrash/config.yaml`

### 配置文件路径
```
/etc/ShellCrash/config.yaml → 软链到 /tmp/ShellCrash/config.yaml
```

### 管理命令
```bash
alias crash='/etc/ShellCrash/start.sh'
crash start     # 启动核心
crash stop      # 停止核心
```
Dashboard：http://192.168.1.1:9999/ui

### 启动方式
必须使用 `/etc/ShellCrash/start.sh start` 手动启动，**不可使用 ShellClash 交互菜单**（其内置的 busybox wget 不支持 `--header` 参数，导致节点测速/更新失败）。

### 更换订阅连接

1. 在电脑端（需代理环境）下载订阅链接：
   ```python
   import requests
   resp = requests.get('你的订阅URL')
   raw = resp.text  # base64 编码的节点列表
   ```

2. base64 解码得到节点链接列表（vless:// / ss:// 等），然后用 Python 转为 Clash YAML：
   ```python
   import base64, yaml, re
   links = base64.b64decode(raw).decode().splitlines()
   # 遍历 links 解析各协议字段，拼成 proxies 列表
   # 最终生成完整 config.yaml（包含 proxy-groups / rules 等）
   with open('config.yaml', 'w') as f:
       yaml.dump(config, f, allow_unicode=True)
   ```

3. 上传到 R3G 并重启：
   ```bash
   # 方式1：SCP 上传
   scp config.yaml root@192.168.1.1:/tmp/

   # 方式2：SSH heredoc 直传
   cat > /tmp/config.yaml << 'EOF'
   <粘贴 config.yaml 内容>
   EOF
   ```

4. 在 R3G 上替换并重启：
   ```bash
   cp /tmp/config.yaml /etc/ShellCrash/config.yaml
   export CRASHDIR=/etc/ShellCrash
   /etc/ShellCrash/start.sh start
   ```

   确认启动成功：
   ```bash
   ps | grep mihomo
   curl -x 127.0.0.1:7890 https://www.google.com -o /dev/null -s -w '%{http_code}'
   ```

## 四、透明代理配置（TUN 模式）

### 核心原理

```
客户端流量 → br-lan → nftables (shellcrash表)
  ├─ DNS (UDP/TCP 53) → redirect :1053 (mihomo fake-ip DNS)
  └─ 其他流量 → fwmark 0x1ed4 → 策略路由 table 100 → default dev utun
                                              ↓
                                    mihomo TUN 虚拟网卡 (utun)
                                              ↓
                                    7890 mixed-port → 节点出口
```

### nftables 防火墙规则（shellcrash 表）

关键链：
- **input**：保护 7890/9999 端口，仅允许本地和 LAN 访问
- **prerouting_dns**：DNS 重定向到 127.0.0.1:1053
- **prerouting**：TCP/UDP 流量打上 fwmark 0x1ed4

**关键修改点**：将 `ip saddr != 192.168.1.0/24` 改为 `iifname != br-lan`，兼容非标准 IP 客户端。

### 策略路由规则
```bash
# fwmark 0x1ed4 → table 100 → default dev utun
ip rule add fwmark 0x1ed4 table 100
ip route add default dev utun table 100
```

### config.yaml 关键配置段
```yaml
tun:
  enable: true
  stack: system        # 必须 system，gvisor 在 mips 上不稳定
  device: utun
  auto-route: false    # 由 nftables 手动控制路由
  auto-detect-interface: false

dns:
  enable: true
  listen: :1053
  enhanced-mode: fake-ip
  fake-ip-range: 28.0.0.0/8

routing-mark: 7894
mode: Rule
mixed-port: 7890
```

### 防火墙重建命令
```bash
nft delete table inet shellcrash

# 然后执行
export CRASHDIR=/etc/ShellCrash
cd /etc/ShellCrash
. ./libs/get_config.sh
sh ./starts/fw_start.sh
```

## 五、DHCP 问题的根源与解决

### 故障现象
手机连接 R3G WiFi → 认证成功 → 显示"正在获取IP地址" → 最终"IP配置失败"

### 根因
OpenWrt 23.05 默认将 dnsmasq 运行在 **ujail 沙箱**中，沙箱限制了原始套接字（RAW socket）权限，导致 DHCP 服务器无法正常构造和发送 DHCP 响应包。

### 历史交互日志
```
DHCPOFFER(192.168.1.x) → 手机回复 DHCPREQUEST(请求旧IP 192.168.1.67)
→ DHCPNAK(wrong server-ID) → 手机获取IP失败
```
手机缓存了旧网络的 IP（192.168.1.x），导致 server-ID 校验失败。

### 修复步骤
```bash
# 1. 备份
cp /etc/init.d/dnsmasq /etc/init.d/dnsmasq.bak

# 2. 注释 ujail 相关行
sed -i 's/^\tprocd_add_jail dnsmasq ubus log$/\t#procd_add_jail dnsmasq ubus log/' /etc/init.d/dnsmasq
sed -i 's/^\tprocd_add_jail_mount/\t#procd_add_jail_mount/' /etc/init.d/dnsmasq
sed -i 's/^\tprocd_add_jail_mount_rw/\t#procd_add_jail_mount_rw/' /etc/init.d/dnsmasq

# 3. 清空租约
> /tmp/dhcp.leases
> /var/dhcp.leases

# 4. 重启
/etc/init.d/dnsmasq restart
```

### 兜底方案（手机端静态IP）
```

子网掩码：255.255.255.0
网关：192.168.1.1
DNS：192.168.1.1
```

## 六、常见故障速查表

| 现象 | 原因 | 解决 |
|------|------|------|
| 搜不到WiFi | radio 被 disabled | `uci set wireless.radio0.disabled=0; wifi reload` |
| WiFi连上但无外网 | nftables/fwmark 规则丢失 | 重新执行 `fw_start.sh` |
| 手机顽固IP不更新 | 手机缓存旧 DHCP 租约 | 手机端"忘记网络"重连 |
| 网络不稳定/断流 | WAN+LAN 双口环路 | 拔掉 LAN 口网线 |
| ShellClash菜单启动失败 | busybox wget 不支持 `--header` | 改用 `start.sh start` 手动启动 |
| 代理端口监听但 TUN 无流量 | fwmark 规则基于源IP而非接口 | nftables 改用 `iifname` 匹配 |
| Dashboard 无法访问 | 7890/9999 被防火墙拦截 | 检查 nftables input 链 |

### 快速验证命令
```bash
# 检查核心状态
ps | grep mihomo

# 检查 nftables 规则
nft list table inet shellcrash

# 检查策略路由
ip rule list | grep 0x1ed4

# 检查 TUN 设备
ip link show utun

# 检查 DNS 代理
nslookup google.com 127.0.0.1 -port=1053
```
