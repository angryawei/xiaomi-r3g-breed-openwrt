03-breed-memboot.txt  —— Breed 控制台内存启动（mem boot）命令序列
适用：小米路由器 3G v1（R3G v1，MT7621A / 128MB NAND / 128MB RAM）
适用场景：initramfs 镜像大于 4MB，Breed Web 界面上传会失败，只能走内存启动
================================================================================

【为什么需要这条路线】
  Breed Web 界面的「固件更新」上传区，实际值接受约 4MB 以内的镜像。
  - 19.07.2 initramfs = 3.38MB  → 可以走 Breed Web 直接上传（见 README 路线二）
  - 23.05.6 initramfs = 5.51MB  → 超过限制，Web 上传必失败，必须走本文件的内存启动
  - 24.10.4 initramfs ≈ 7MB     → 同上，走内存启动

【前提】
  1. 路由器已刷好 Breed（进入方法：断电 → 按住 Reset 不放 → 插电 → 等约 5~8 秒
     → 浏览器访问 192.168.1.1，看到 Breed Web 控制台）。
  2. 电脑与路由器网线直连，电脑侧网络设置为：
         IP     192.168.1.2
         掩码   255.255.255.0
         网关   192.168.1.1（可不填）
  3. 电脑上有一个能被 Breed 访问的 HTTP 服务器，且**必须是 HTTP/1.1**：
     见下方「第一步」的两种做法。

--------------------------------------------------------------------------------
第一步：在电脑上起 HTTP 服务，把固件放到能被 wget 取到的位置
--------------------------------------------------------------------------------
把要启动的 initramfs 镜像复制到一个空目录（示例：D:\r3g-http\），
在该目录下执行：

  【做法 A：Python 自带服务器（推荐 Python 3）】
      cd /d D:\r3g-http
      python -m http.server 8001 --bind 0.0.0.0
      注意：Python 3.7+ 的 http.server 返回 HTTP/1.0 响应头，
            Breed 的 wget 对 HTTP/1.0 兼容性差，若报 "Connection aborted"
            请改用做法 B。

  【做法 B：强制 HTTP/1.1 的小服务器（最稳，实测成功率最高）】
      在 D:\r3g-http 下新建 serve.py，内容：

          import http.server, socketserver, os
          os.chdir(os.path.dirname(os.path.abspath(__file__)))
          class H(http.server.SimpleHTTPRequestHandler):
              protocol_version = "HTTP/1.1"          # 关键：必须是 1.1
              def end_headers(self):
                  self.send_header("Connection", "close")
                  super().end_headers()
          socketserver.TCPServer.allow_reuse_address = True
          with socketserver.TCPServer(("0.0.0.0", 8001), H) as httpd:
              print("serving on 8001 ...")
              httpd.serve_forever()

      然后执行：
          python serve.py

  4. Windows 防火墙放行 8001 端口（首次运行会弹窗，选「允许」）：
     若无弹窗，管理员 PowerShell 执行：
         New-NetFirewallRule -DisplayName "R3G-HTTP-8001" -Direction Inbound -Protocol TCP -LocalPort 8001 -Action Allow

  5. 先在电脑浏览器访问 http://192.168.1.2:8001/ ，能列出文件列表即正常。

--------------------------------------------------------------------------------
第二步：进入 Breed 控制台
--------------------------------------------------------------------------------
  Web 界面 → 左侧「高级设置」或顶部「控制台」标签 → 打开命令行（Console）。
  部分 Breed 版本无 Web 控制台，则用 telnet：
      telnet 192.168.1.1
      （用户名/密码：无，直接回车）

  ★ 关键约束：Breed 的 Web 页面与 telnet 控制台**互斥**，同一时刻只能用一个。
    用 telnet 时先关掉浏览器页面，反之亦然。

--------------------------------------------------------------------------------
第三步：下载 initramfs 到内存（wget）
--------------------------------------------------------------------------------
在 Breed 控制台依次执行（把文件名换成你实际的 initramfs 文件名）：

  wget http://192.168.1.2:8001/openwrt-23.05.6-ramips-mt7621-xiaomi_mi-router-3g-initramfs-kernel.bin 0x80001000

  说明：
    - 0x80001000 是这块板子内核的常规加载地址，与 uImage 头部标注的
      "Load Address" 一致（可用本目录脚本 02-split-sysupgrade.py --check 查看）。
    - 下载要等一会儿（5.5MB 走百兆网约 1~3 分钟），期间不要断电。

  如果下载失败，优先检查：
      ① 电脑防火墙未放行 → 见第一步第 4 点
      ② Python 默认服务器返回 HTTP/1.0 → 改用做法 B
      ③ 文件名打错（Breed 的 wget 不支持目录列表，必须写全文件名）
      ④ 路由器与电脑不在同一网段（电脑必须是 192.168.1.2）

--------------------------------------------------------------------------------
第四步：校验内存里的内容是不是真的 uImage
--------------------------------------------------------------------------------
  mem read 0x80001000 16

  正确输出开头应为：
    80001000: 27 05 19 56 ...

  27 05 19 56 就是 uImage 魔数。若读出来全是 00 或 FF，说明下载失败，
  回到第三步重试，**不要**直接 boot。

--------------------------------------------------------------------------------
第五步：内存启动
--------------------------------------------------------------------------------
  boot mem 0x80001000

  参数含义：boot mem <uImage 头地址>，由 Breed 解析 uImage 头后正确装载内核。
  等待约 30~75 秒，然后：

      ping 192.168.1.1

  能 ping 通、浏览器打开 http://192.168.1.1 出现 OpenWrt LuCI 登录页，
  即进入临时（内存）系统。

--------------------------------------------------------------------------------
第六步：在临时系统里刷正式固件
--------------------------------------------------------------------------------
  内存系统里**不能**用 SSH 执行刷写类命令（initramfs 恢复模式有 LuCI ACL 限制，
  ubus file.exec / uci commit 会被拒），正确做法：

      浏览器打开 http://192.168.1.1
      → 系统 → 备份/升级 → 刷写新固件
      → 取消勾选「保留配置」（首次刷入务必不保留）
      → 上传 openwrt-*-squashfs-sysupgrade.bin → 刷写

  刷完自动重启，之后访问 192.168.1.1 就是 NAND 上的正式 OpenWrt 了。

--------------------------------------------------------------------------------
【踩坑：这些命令是错的，别用】
--------------------------------------------------------------------------------
  1. 错误做法：flash bank 0x80001000 0x80000000 <大小>
     报错：Specified flash bank does not exist
     原因：内存启动根本不经过 flash bank，这条命令是多余的、错误的。
     处理：直接跳过，用 boot mem。

  2. 错误做法：boot linux 0x80001000
     现象：卡死 / ping 报 TTL expired in transit。
     原因：boot linux 直接跳到 uImage 头地址执行，而 initramfs 不是可执行镜像。
     处理：改用 boot mem。

  3. 少数 Breed 版本会忽略 wget 后面的地址参数，把文件下到默认地址，
     导致 boot mem 0x80001000 装不到东西。此时改用：
         wget http://192.168.1.2:8001/<文件名> 0x81000000
         mem  read 0x81000000 16        → 应看到 27 05 19 56
         boot mem  0x81000000
     0x81000000 同样安全（避开内核解压区），不影响启动。

  4. 在内存系统里执行了 reboot / 断电 → 内存系统消失，Breed 会按 autoboot
     启动 NAND 上的原厂固件（访问 192.168.31.1 是小米界面）。
     这是正常回退，**不是变砖**，重新走一遍内存启动即可。

  5. 本流程仅适用 R3G **v1**（128MB NAND）。v2 是 16MB SPI NOR，硬件不同，
     固件不通用，照此操作必砖。判定方法见仓库根 README.md。
